# Условное использование аппаратуры телефона

Проверено по текущему исходному коду 2026-10-05. Физический телефон отсутствует.
Этот документ описывает подключение и критерии допуска, а не результат измерения.

## Что уже есть

| Возможность | Текущий путь | Граница |
| --- | --- | --- |
| GPU для YOLO | `ModelService` / flutter_vision, настройка `useGpu`, повтор загрузки на CPU при ошибке | Успешная загрузка делегата не доказывает offload всех операций или выигрыш задержки |
| GPU для MiDaS | NCNN Vulkan, provider сообщает реальный native `isVulkan`; worker сохраняет этот backend | NCNN — отдельный runtime; наличие NPU не ускоряет его автоматически |
| ARCore Raw Depth | `HardwareDepthSession` / `HardwareDepthProvider` | В Core независимая ARCore-камера заблокирована политикой одного владельца камеры |
| NPU | Нет подключённого NPU-backend текущего detector runtime | Нужен отдельный совместимый адаптер и проверка модели/операций/драйвера |
| LiDAR на iPhone | Нет проверенного Core runtime-пути ARKit sceneDepth | Нужен отдельный iOS-адаптер и подтверждение поддержки; Android ARCore не заменяет его |

YOLO `useGpu` по умолчанию false (`Settings`). Текущий путь включается настройкой,
а не автоматическим сравнением CPU/GPU. `_lastLoadGpu` хранит запрошенный режим;
после CPU fallback он не является подтверждением фактического GPU backend.
Для автоотбора нужен отдельный receipt реального backend и результатов проверки.

ARCore Depth может получать глубину из движения и использовать ToF, если он
доступен. Поддержка Depth не является доказательством наличия физического ToF
или LiDAR. Во время работы кадры глубины могут быть недоступны.

## Порядок подключения

1. Разделить состояния: обнаружено оборудование, доступен runtime/драйвер,
   совместима конкретная модель, прошла инициализация, получен корректный результат,
   измерено преимущество, разрешено использование для конкретной функции.
   Название телефона, whitelist и сохранённая настройка не заменяют проверки.
2. Для YOLO сравнить существующие CPU/GPU с отдельным LiteRT NPU-кандидатом.
   Не заменять одновременно detector и depth. Для MiDaS сравнивать NCNN CPU/Vulkan;
   перенос на иной runtime требует отдельной parity-проверки модели.
3. Для metric depth обеспечить одного владельца RGB-камеры: aligned RGB/depth,
   intrinsics, pose/transform, timestamps и подтверждённое преобразование clock.
   Не включать нынешнюю самостоятельную ARCore-сессию параллельно Flutter camera.
4. Сравнить одинаковые входы и решения: пропуски/поздние опасности, ложные остановки,
   unsafe continues, p50/p95/p99, память, нагрев и расход батареи. Проверить ошибки
   и длительную работу, а затем выбрать backend по измерениям на этом устройстве.
5. При отказе accelerator перейти на проверенный CPU-путь. При потере metric
   depth перейти на явно relative NCNN/недоступность; не продолжать называть
   результат метрическим. Устаревшие/несогласованные кадры отклонять.
6. Переключение только между сеансами с завершением владельца старого backend.
   Не запускать benchmarking или вторую камеру во время активных предупреждений.
   Failed capability probes не повторять каждый кадр.

Экспериментальные пространственные ветки сохраняют shadow и
`promotionAllowed=false`; аппаратное ускорение не разрешает assistive promotion.
100 ms / 2 s contracts и правила unknown не ослабляются.

## Проверка перед автоматическим выбором

Нужны tests отсутствующего устройства/драйвера, неподдерживаемых операций,
ошибки инициализации/inference, ложного capability report, несовпадающих RGB/depth,
потери tracking, stale clock/frames, background/resume и переключения backend.
Затем named-device profile, release confirmation и controlled scenarios.

NPU-кандидат следует проектировать через актуальный LiteRT/runtime производителя.
NNAPI deprecated начиная с Android 15; наличие NNAPI driver не является
подтверждением NPU и не гарантирует реальную аппаратную делегацию.

Официальные источники, проверенные при подготовке:
- [ARCore Depth: support, enabling, ToF and unavailable frames](https://developers.google.com/ar/develop/java/depth/developer-guide).
- [LiteRT Android: CPU/GPU/NPU runtimes](https://developers.google.com/edge/litert/android).
- [Android NNAPI deprecation and fallback](https://developer.android.com/ndk/guides/neuralnetworks).

Результат текущего этапа: обследован существующий код и записан проверяемый
порядок подключения. Новые NPU/LiDAR backend не установлены и не включены.
