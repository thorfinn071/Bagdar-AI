# Сокращённый обзор одной камеры: результат 2026-10-11

Удалены два геометрически избыточных ракурса из прежнего синтетического
обзора. Десять оставшихся сохранили полные измерения на 6/6 свободных сценах
и blocked на 6/6 опасных при условном расписании 120 кадров/с. Запас до
истечения старейшего измерения вырос с 6,333 до 23 мс. **Ложные STOP обычной
камеры пока не исправлены:** реальные сбор данных и скорость поворота камеры
не проверены, а полный текущий объём одним обычным ракурсом не подтверждён.

## Что изменилось в коде

[Планировщик](../tool/model_benchmark/plan_camera_scan_geometry.py) выбирает
подмножество только по intrinsics, pose и геометрии запроса. Глубина, метки
опасности и меши сцен в выборе не участвуют. Он проверил 1 426 392 box nodes
с той же сеткой объёма/пола и subdivision depth=4, затем перебрал 4095
непустых подмножеств. Единственный минимальный mask=3069 оставил индексы
0, 2, 3, 4, 5, 6, 7, 8, 9, 11. Это offline-план фиксированных двенадцати
pose; оптимальность для других ракурсов или оптики не утверждается.

[Независимый геометрический контроль](../tool/model_benchmark/single_camera_minimal_witnesses.py)
применяет прямую perspective projection к точкам вместо box-plane recursion.
Для каждого из десяти выбранных ракурсов он нашёл точку требуемого объёма,
видимую только этим ракурсом среди исходных двенадцати. Все десять действительно
необходимы в этом конечном наборе. Ни точки, ни попадание boxes в frustum
не доказывают свободность, отсутствие occlusion или опору пола.

Новые [эксперимент](../test/single_camera_minimal_scan_experiment_test.dart)
и [измеритель времени](../tool/model_benchmark/profile_minimal_scan.dart)
используют прежний indexed whole-pixel producer, evaluator и age gate.
Пиксели, модели, границы глубины/высоты, запрос 0,9 × 1,85 м и 0,2–3,5 м,
TTL 100000 мкс, motion/history и ordinary runtime не менялись.

## Измерения на известных статических данных

Двенадцать прежних сцен, две версии обзора, семь расписаний: 168 trials.
Исходные capture timestamps сохранены в original control. В отдельных копиях
время присвоено последовательно выбранным ракурсам по round(i / fps), со
стартом через 2 мс. Это counterfactual clocks, не физическая съёмка.
Метки читаются после потребителей. Таблица показывает released measurement,
а не команды движения приложения.

| Расписание | 12 ракурсов: clear / blocked / unavailable | 10 ракурсов: clear / blocked / unavailable |
|---|---:|---:|
| Исходные 2,2 с | 0 / 0 / 12 | 0 / 0 / 12 |
| Условные 30 кадров/с | 0 / 0 / 12 | 0 / 4 / 8 |
| Условные 60 кадров/с | 0 / 4 / 8 | 0 / 6 / 6 |
| Условные 90 кадров/с | 0 / 6 / 6 | 0 / 6 / 6 |
| Условные 120 кадров/с | 6 / 6 / 0 | 6 / 6 / 0 |
| Условные 120 кадров/с + 15 мс compute | 0 / 0 / 12 | 6 / 6 / 0 |
| Условные 120 кадров/с + 25 мс compute | 0 / 0 / 12 | 0 / 0 / 12 |

При десяти ракурсах и условных 120 кадрах/с старейший capture имеет возраст
77 мс в начале, 92 мс после заданных 15 мс и 102 мс после заданных 25 мс.
Последний вариант отклонён полностью: observation и decision не выдаются.
Для 90 кадров/с остаются только девять свежих ракурсов; полного clear нет.
Условный порядок десяти pose требует до 9692,4°/с между соседними кадрами.
Реальная возможность такой съёмки не установлена. Синтетическая неподвижность
сцен не доказывает актуальность нескольких кадров в движущемся мире.

В 84 hazard trials нет measuredClear. Ещё 84 whole-packet fault trials
(relative units, invalid pixels, missing height/first-return, bad pose,
wrong model, mixed sessions) также не дали measuredClear. Эти контролируемые
ошибки не заменяют испытаний реальной точности и частичных неисправностей.

## Фактическое время обработки

Финальные значения находятся в `elapsed.json` и `elapsed-validation.json`
рядом с experiment.json. Измеряется Windows Dart AOT, предварительно загруженные
пакеты, один warmup, три раунда с чередованием двух вариантов внутри каждой
сцены. В advancing replay clock включены реальные source/evaluator/gate
вычисления; условные capture offsets по-прежнему не являются физическими.
Загрузка, camera acquisition, transport, neural inference, аудио и вибрация
не входят в этот измеренный pipeline. Условия CPU/thermal не контролировались.

| Набор | Измерений | p50 pipeline, мс | p95 pipeline, мс |
|---|---:|---:|---:|
| Все 12 ракурсов | 36 | 350,241 | 607,087 |
| Выбранные 10 ракурсов | 36 | 292,632 | 474,252 |

Сокращение набора уменьшило медиану примерно на 16,5%, p95 на 21,9% в этом
запуске. Ни один результат не уложился в срок: **72/72 expiredAfterCompute**,
observation/decision не выданы. Для десяти ракурсов compute budget 23 мс;
измеренная медиана 292,632 мс превышает его примерно в 12,7 раза. Эти числа
характеризуют этот desktop workload, без доказательства Android latency.

Первый timing run совпал с повтором Flutter-тестов. Он сохранён отдельно как
`elapsed-concurrent-flutter.json` и исключён из итоговых значений. Финальный
run выполнен после завершения тестов, без запущенной нами параллельной нагрузки.

## Проверка и оставшийся барьер

До scoring заморожены 1359 файлов вместе с предыдущей цепочкой.
Независимый verifier прошёл 3000 проверок целостности/часов/выборки/статусов.
Отдельный elapsed audit прошёл для всех 72 измерений, включая вычисление
процентилей и сохранение исходного oldest capture при фактической задержке.
Повтор матрицы совпал byte-for-byte. 63 Flutter tests прошли: одна новая
матрица, 21 scan-window, 23 age-gate и 18 observability tests. Static analysis
двух новых Dart-файлов без замечаний. Production Dart и native не изменялись;
полный RC и новый Android runtime в этом этапе не запускались.

Выбор десяти ракурсов уменьшил избыточность стенда. Доказательства измерений
обычного телефона остаются открытыми: физический источник metric whole-pixel
bounds, их alignment/error, current scene и задержка. MiDaS остаётся относительной
глубиной. Старые 14/14 и 34/34 ложных STOP не имеют нового успешного runtime
прогона; обычная камера не подключена к этому эксперименту. Все artifacts
сохраняют shadow, promotionAllowed=false, canAuthorizeMovement=false и
falseStopReductionEstablished=false. Телефон сейчас недоступен по ответу
пользователя; действий от пользователя для выполненного offline этапа не требуется.
