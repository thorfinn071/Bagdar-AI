# Протокол camera-temporal-passage-v1, до реализации и просмотра test

Следующий ограниченный эксперимент проверяет подтверждённый дрейф RANSAC
на неизменном входе. Предыдущий `test-association-wide-08` теперь является
известной регрессией. Он не входит в новое независимое доказательство.

Новая обёртка повторяет подбор RANSAC samples для каждого входа, сохраняя
состояние обычного tracker, fusion и planner. Веса, preprocessing, нормализация,
число итераций, пороги препятствий и допуска прохода не меняются. Метки сцены,
RGB hash, прошлый ожидаемый action и скрытая геометрия не являются её входами.
Прежняя реализация, freeze и отчёты остаются доступными без изменений.

До первого test фиксируются generator и полный split по геометрическим сценам:
6 validation, 12 test. Validation: широкий проход, дверь, наружная стойка,
перекладина, приближение коробки, пересечение пути. Test: два широких прохода,
дверь, наружная стойка, перекладина, внутренняя и субпиксельная стойки,
приближение, пересечение, удаление коробки, вращение и перенос камеры.
Параметры отличны от прежних корпусов. После development сохраняется отдельный
freeze реализации и development-отчёта, затем впервые запускается test.

В статических сценах 13 настоящих RGB/depth кадров: anchor, девять направлений,
возврат через 2 с и две проверки через 200 мс. Relative detector принимает
четыре anchor кадра; метрический producer использует осмотр в разрешённом
статическом synthetic режиме. Это по-прежнему не NN-трекинг вращающейся камеры.
В семи временных сценах — по семь разных кадров через 200 мс с движущимся
объектом/камерой. Нейросеть обрабатывает каждый RGB. Только текущая первая
видимая глубина поступает producer, обычный возраст 400 мс: старый осмотр
нельзя объявлять актуальным для движущейся сцены. Неполный обзор остаётся
неизвестным; этот эксперимент не реализует предсказание латерального движения.

Сравнение: NCNN контроль; текущая привязка с stateful RANSAC; та же привязка
с повторяемым подбором RANSAC. Измерять false stops на достаточно наблюдаемых
статических проходах, пропущенные/своевременные/поздние опасные остановки,
небезопасные continueForward и необоснованные measuredClear. Для временных
сцен публиковать события после фактического входа препятствия в защищаемый
объём, тренды tracker, observability и причины planner. Остановки из-за
unknown не выдавать за доказательство точной оценки движения.

Критерий: меньше false stops, zero unsafe/unjustified в новой ветке, сохранение
остановок при настоящих опасностях и неизвестности. Отрицательные проверки:
одинаковый вход после другого кадра, changed depth, null/stale/invalid input,
реальный approach без сброса tracker, история остановки, provider/pose/session
и expiry из прежних tests. Функциональный --check добавить в Core RC,
время desktop хранить отдельно. Flutter проверки строго последовательны.

Только synthetic desktop shadow, promotionAllowed=false. Нет допуска телефона
или ходьбы; достижение всех нулей не доказывает универсальную безопасность.
