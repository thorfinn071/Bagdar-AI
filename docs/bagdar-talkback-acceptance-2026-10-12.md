# Bagdar: протокол проверки самостоятельного использования на Android

Дата: 2026-10-12. Статус: **not_run**. В текущем срезе подключённых ADB-устройств нет. Этот документ — готовый сценарий проверки, а не результат её проведения.

## Подготовка и запись конфигурации

Проводить неподвижно в подготовленном помещении. Участник уже умеет пользоваться включённым TalkBack. До исследования с участниками разработчик проходит критические сценарии. Начать с одного названного Android среднего класса с 6–8 ГБ RAM, затем повторить на другом Android/производителе. Указать реальные версии, не заменять их словами «последняя».

| Поле | Заполнить перед запуском |
|---|---|
| Модель, RAM, Android/build | не измерено |
| APK flavor/type, SHA-256, версия исходников | не записано; хеш готовой сборки в `output/accessible-transitions-2026-10-12/validation.json` |
| TalkBack, TTS engine и голос для каждого языка | не записано |
| Язык, размер текста, ориентация, тема, шторка | отдельная запись каждой конфигурации |
| Аудиомаршрут, громкость TalkBack/Bagdar | не записано |
| Тестировщик, дата, test transport SOS | не записано |

Для SOS нужна отдельная тестовая конфигурация с подменённым транспортом и проверкой, что реальные SMS, звонки и внешняя отправка невозможны. Обычный Core debug APK **не объявляется** такой конфигурацией. Пока подмена не проверена, сценарии SOS на телефоне остаются `not_run`. Не вызывать реальный номер экстренных служб. Нативное поведение шторки, речи, камеры и выбора контакта нельзя получить из widget-тестов.

## Как фиксировать результат

Для каждого сценария записать: конфигурацию; шаги; произнесённые имя/роль/состояние; последовательность accessibility focus до и после перехода; наложение речи; результат; каждую подсказку или вмешательство; ссылку на запись/иерархию при наличии согласия. Статусы: `pass`, `fail`, `not_run`, `blocked` с причиной. Результат относится только к выполненной конфигурации.

Каждый критический сценарий проверить последовательными свайпами TalkBack и обычной активацией, затем исследованием касанием. Клавиатурный focus и экранная рамка Flutter не заменяют accessibility focus TalkBack. Не считать `accessibleNavigation` точным детектором включённого диктора.

## Сценарии и ожидаемое поведение

| ID | Действия | Критерий pass | Сейчас |
|---|---|---|---|
| A01 | Чистое состояние → язык RU → без помощника → ограничения | Контекст и выбранные варианты читаются; согласие требует явного действия; помощник/микрофон не обязательны | not_run |
| A02 | Обычный сигнал → личное подтверждение → STOP; попробовать «не слышу/не чувствую» | Воспроизведение не считается ответом человека; причина и альтернативный путь доступны | not_run |
| A03 | Упражнение → ошибка → повтор той же ошибки → исправление | Ошибка слышна повторно; focus остаётся управляемым; повтор/остановка инструкции доступны | not_run |
| A04 | Ошибка загрузки/хранения → повтор → обучение без сохранения | Понятно, что не сохранено; поздний ответ не запускает камеру; допуск к осмотру не возникает | not_run |
| A05 | Отказать камере → повторить → permanent deny → Android Settings → возврат | Причина и восстановление читаются; возврат не обходит обновление проверки | not_run |
| A06 | Положение телефона → неудачная проверка → повтор → итог → осмотр на месте | Итог называет недостающий шаг; устаревший результат не даёт допуск | not_run |
| A07 | Осмотр → состояние → повтор вслух → закрытие → справка → закрытие | Команды доступны; речь запускается осознанно; после закрытия понятна точка продолжения | not_run |
| A08 | Осмотр → настройки → контакт → ввод с клавиатурой → ошибка → системный выбор контакта → отмена/возврат | Поле имеет имя; ошибка читается; фокус/клавиатура возвращаются управляемо; отмена не меняет контакт | not_run |
| A09 | Настройки → QR export → назад; QR import → назад | Понятен экран и способ выхода; камера восстанавливается только в разрешённом состоянии; ошибки имеют восстановление | not_run |
| A10 | Языковые пакеты → подтверждение удаления → отмена/назад | Диалог имеет контекст; возврат к выбранному пакету; отмена не удаляет пакет | not_run |
| A11 | Повторить A07–A10 со шторкой | Критические действия доступны и при исследовании касанием; невидимость не лишает управления | not_run |
| A12 | Фон/возврат из обучения и осмотра → завершение → повторный вход | Готовность обновляется по существующему gate; нет устаревшего «готово», самопроизвольного входа или потерянного выхода | not_run |
| A13 | Тестовый SOS поверх контакта/QR/языковых пакетов и вложенного диалога | Внутренние окна закрываются, приоритетный SOS доступен; поздние ответы не открывают окна; после SOS есть понятный путь восстановления | not_run |
| A14 | Тестовый отсчёт → случайная отмена → просроченное подтверждение → валидное подтверждение; отдельный прогон истечения/ошибки | Одна активация не отменяет; результат правдив; отправка единственная и только в fake transport | not_run |
| A15 | Bagdar + TalkBack → повтор/остановка → смена экрана → потеря голоса/аудиомаршрута, звонок | Обычная речь не захватывает управление; критическая речь сохраняет приоритет; отказ не выдаётся за слышимость | not_run |

A09 отдельно выявляет доступность существующего подтверждения QR удержанием. Этот путь пока не считается подтверждённым для TalkBack; при барьере заменить его обычным именованным действием с явным подтверждением. Системный выбор контакта находится вне Flutter Navigator: закрытие внутренних маршрутов не доказывает управление внешним Android-экраном.

## Минимальное покрытие и решение

Сначала RU, 100%, portrait, динамик, шторка выключена. Затем критический путь A01–A08/A11–A14 в RU/KK/EN, при 200% текста; длинные формы также landscape; светлая и тёмная темы. Для речи записать реально выполненные маршруты: динамик, доступная гарнитура, Bluetooth при наличии. Непроверенные комбинации перечислить отдельно. Условные системные отказы воспроизводить контролируемым способом и описывать способ подмены.

При недостижимом критическом действии, непреднамеренном SOS, ложной готовности или отсутствии восстановления — `fail`, исправление и повтор затронутого маршрута до исследования с участниками. Не усреднять критический отказ успешными сценариями. После developer acceptance — добровольный пилот с пятью незрячими участниками по [пакету 5 плана](bagdar-independent-use-improvement-plan-2026-10-11.md). Измерять выполнение без помощи, подсказки, тупики, ошибки SOS и понимание ограничений; время — диагностическая метрика без выдуманного порога.

Положительное прохождение подтверждает конкретные задачи на конкретных конфигурациях. Оно не доказывает безопасность ходьбы, корректность perception или готовность всех Android-устройств. Методика ручной проверки с TalkBack соответствует [рекомендациям Android](https://developer.android.com/guide/topics/ui/accessibility/testing?hl=en).
