# Одна камера: проверка наблюдаемости прохода — 11 октября 2026

**Основное ограничение пока не устранено.** Новый код проверяет, помещается ли
требуемый объём в кадр, и сохраняет явный ближний пробел. На известных
синтетических кадрах исходный ракурс содержит полное сечение тела и пола только
с **1,738 м**, тогда как запрос начинается с **0,20 м**. Сокращённые запросы
дальнего участка также не дали ни одного `measuredClear`. Снижение ложных STOP
не установлено; 94 программных теста проверяют контракты, а не готовность навигации.

## Что сделано в коде

Добавлен отдельный `SingleCameraObservabilityPreflight` в
[single_camera_observability.dart](../lib/safety/perception/single_camera_observability.dart).
Он решает пересечение плоскостей поля зрения с полным поперечным сечением
заданного прохода, включая пол. Результат содержит видимый интервал, ближний и
дальний пробелы, а также причину отказа. Даже полное попадание в кадр не является
измерением свободного пространства: `canCertifyFreeSpace=false` и
`canAuthorizeMovement=false` всегда.

До геометрии проверяются метрическая калибровка и поза, соответствие frame,
session, transform, model, reference и clocks. Будущие кадры и возраст свыше
100000 мкс отклоняются. Относительная глубина и отсутствие подтверждённой
калибровки также дают отказ. Геометрический расчёт намеренно не использует
значения пикселей: весь depth может быть invalid, а объём всё равно геометрически
помещаться в кадр. Это не разрешает движение.

Модуль пока вызывается только тестами. Его подключение к обычному runtime не
выполнялось. Старые производители, пороги, модели и STOP history сохранены.

## Эксперимент

Протокол и пять новых исходных файлов заморожены до запуска вместе с прежними
источниками и receipts: всего **288 файлов**. Использованы все **35 известных
кадров** эксперимента camera-view-coverage: пять ракурсов и семь случаев на
ракурс. Это диагностическое повторное использование, без нового независимого
holdout и без нового нейросетевого inference.

Исходный запрос: ширина 0,90 м, headroom 1,85 м, верхняя граница тела 1,90 м,
дистанция 0,20–3,50 м, допуски пола 0,05 м. Для каждого ракурса сохранены прежние
синтетические intrinsics, pose и first-return arrays. Калибровочные флаги относятся
к синтетическому стенду; на реальном телефоне они не подтверждены.

| Ракурс | Начало полного сечения в кадре | Ближний пробел от 0,20 м | Полный запрос: clear / blocked / unavailable | Дальний запрос: clear / blocked / unavailable |
|---|---:|---:|---:|---:|
| Исходный: высота 1,42 м, наклон 12° вниз | 1,738 м | 1,538 м | 0 / 4 / 3 | 0 / 3 / 4 |
| Высота 1,42 м, камера горизонтально | 2,735 м | 2,535 м | 0 / 4 / 3 | 0 / 1 / 6 |
| Высота 0,975 м, камера горизонтально | 1,878 м | 1,678 м | 0 / 4 / 3 | 0 / 3 / 4 |
| Высота 0,975 м, наклон 25° вниз | Нет в диапазоне запроса | Нет полного сечения | 0 / 3 / 4 | Не сформирован |
| Идеальный широкий контроль, не оптика телефона | 0,200 м | 0 м | 0 / 4 / 3 | 0 / 4 / 3 |

Во всех 35 полных запросах прежний производитель/evaluator воспроизвёл прежние
результаты точно: **0 clear, 19 blocked, 16 unavailable**. Дополнительно проверены
28 запросов внутри геометрически видимого дальнего интервала: **0 clear,
11 blocked, 17 unavailable**. Причины включают `unobservedBody`,
`unobservedFloor`, `missingMeasurements` и `blockedSection`. Значит, попадание
объёма в кадр само по себе не устраняет недостаток first-return/floor evidence.

Дальний запрос намеренно отличается от полного. Для всех 28 результатов
проверено, что он не покрывает полный recovery volume и не применим к исходному
запросу. Перемещение начала запроса за слепую зону не считается исправлением.

Прежний runtime receipt этих 35 кадров содержит **10/10 ложных STOP** на
свободных кадрах и **25/25 STOP** на опасных. Здесь runtime заново не запускался:
его receipt проверен по hash, исходные исходы сохранены. Отдельные прежние
результаты одного вида **14/14 ложных STOP** и независимого набора
**34/34 ложных STOP, 50/50 hazard STOP** тоже сохранены по hash. Новые знаменатели
к ним не добавляются.

## Проверки

- **18 новых unit tests**: полный/частичный/отсутствующий интервал, боковой
  сдвиг, обратная камера, граница 100 мс, future/stale, относительные единицы,
  плохая поза и reflection, несовпадение identity/clock, отсутствие метрической
  калибровки, нечисловые запросы и отсутствие движения при invalid depth.
- **1 новый experiment test**: все 35 исходных запросов, 28 частичных запросов,
  неизменность прежних результатов и побайтное воспроизведение нового JSON.
- Вместе с прежними camera source, passage contract и recovery replay прошли
  **94 Flutter-теста**, последовательно с `--concurrency=1`.
- Targeted Dart analysis: без замечаний; format check: 0 изменений.
- Независимый Python verifier: integrity pass, **60494 проверки проекций**.
  Он проецирует углы напрямую, проверяет свидетельства внутри/вне найденного
  интервала и прежние body/floor cell maps. Для отсутствующего интервала проверка
  67 дистанций является выборочным отрицательным контролем; аналитическое
  пересечение плоскостей выполняется в Dart. Эти проверки не доказывают
  свободность или отсутствие препятствий между пикселями.
- График просмотрен визуально. Прежние замороженные source/receipt hashes прошли.

Артефакты находятся в `scratch/single-camera-observability-2026-10-11/`:
`preregistration.json`, `experiment.json`, `validation.json`, `regression-tests.log`,
`independent-verifier.log`, `observable-intervals.png` и `.svg`.

## Что требуется для настоящего исправления

Сейчас измерение свободного пути требует текущего покрытия всего объёма
0,20–3,50 м. У проверенных обычных ракурсов часть этого объёма находится вне
кадра. Новый модуль делает это ограничение явным, но не создаёт отсутствующие
измерения. Замена depth model также сама по себе не расширяет поле зрения.

Следующий архитектурный этап должен предъявить источник данных для ближней
зоны и независимые метрические error bounds. Возможные дополнительные ракурсы,
более широкая оптика или перенос прошлых наблюдений по позе требуют отдельных
проверок. Для переноса особенно нужны доказательства актуальности, видимости,
окклюзии, движения объектов и ошибок pose в пределах прежнего TTL. Старые
измерения нельзя автоматически объявить текущими. Здесь такие возможности не
реализованы и не признаны работоспособными.

Цель полной навигации сохранена. Смена продукта на предупреждение только о
видимых опасностях означала бы другое обещание пользователю и не засчитывалась
бы как снижение ложных STOP исходной навигации.

Для проверки реального источника понадобится названный телефон и capture по
подготовленной [Research-инструкции](research-capture-guide-2026-10-11.md).
Телефон пока неизвестен. MiDaS остаётся относительной глубиной; физическое
выравнивание, метрические ошибки, latency, Android runtime, нагрев и
контролируемая ходьба не проверены в этом этапе. Полный Core RC не запускался.
Режим остаётся `shadow`, `promotionAllowed=false`, `ordinaryCameraWired=false`.
